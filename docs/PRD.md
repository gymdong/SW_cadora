## 1. 제품 개요

### 1.1 배경과 문제

대학생 개발 팀, 공모전 참가자, 프리랜서, 초기 스타트업 개발자는 과제와 팀 프로젝트 여러 개를 동시에 진행한다. 이 과정에서 브라우저 로그인 계정, 다운로드 파일, 서버 포트, 환경변수, 참고 문서가 한 컴퓨터 안에서 뒤섞인다. 팀원이 새로 참여하면 저장소뿐 아니라 실행 명령, 문서 링크, 계정 초대, 공용 자료 등을 다시 설정해야 한다.

AI 코딩 에이전트를 병렬로 활용할수록 새로운 문제가 생긴다. 팀원마다 다른 에이전트에 유사한 일을 맡기거나, 한쪽이 DB 스키마·의존성·실행 환경을 바꿨는데 다른 에이전트는 이전 상태를 기반으로 작업할 수 있다. Git이 결과물을 합칠 때 충돌을 보여 주더라도 작업 진행 중인 시점의 조율은 별도의 도구가 필요하다.

### 1.2 제품 비전

Cadora는 프로젝트별 작업환경의 경계를 만들고 그 경계를 팀 단위로 공유하는 데스크톱 앱이다. 프로젝트 안에는 브라우저 세션, 전용 폴더, 터미널, 실행 프로세스, 참고 자료, AI 에이전트 관련 설정과 활동 메타데이터가 연결된다. 사용자는 여러 워크스페이스를 동시에 운영할 수 있다.

팀장은 GUI에서 공동 환경을 설정하고 팀원을 초대한다. 팀원은 자신만의 계정과 개인 설정을 유지하면서 같은 공통 환경을 받아 사용한다. Cadora는 자체 코드 에디터나 자체 AI 모델 대신 VS Code, Claude Code, Codex, Discord처럼 이미 익숙한 도구를 연결·실행·관찰한다. 에이전트 실행·세션 유지·상태 감지는 오픈소스 에이전트 런타임 [Herdr](https://herdr.dev)를 엔진으로 활용하고(대체 경로: 자체 node-pty 구현), Cadora는 그 위에 터미널 밖의 환경 격리와 팀 레이어를 만든다.

### 1.3 핵심 가치 제안

1. **프로젝트 간 혼선 감소**: 로그인·파일·실행 환경을 프로젝트 기준으로 구분.
2. **팀 온보딩 단순화**: 팀장이 준비한 공통 환경을 팀원이 재설정 없이 받아 시작.
3. **AI 병렬 작업 조율**: 실행 상태와 변경 메타데이터를 종합하여 중복 작업·공유 자원 충돌 가능성을 사전 경고.

### 1.4 제품 포지셔닝

프로젝트 관리 앱의 일반적인 할 일·칸반·채팅 기능보다, 프로젝트별 독립 작업환경 및 팀 단위 환경 동기화가 제품의 중심이다. 기존 도구의 대체재가 아니라 작업 환경을 묶는 상위 레이어로 정의한다.

| 기존 도구 | 하는 일 | Cadora와의 관계 |
|---|---|---|
| Herdr, Conductor 등 에이전트 관리 도구 | 한 사람이 여러 에이전트를 터미널·worktree 단위로 실행하고 상태를 본다 | 런타임으로 활용하거나 같은 역할을 대체 구현. 팀 기능은 없다 |
| Wavebox, Shift 등 다중 계정 브라우저 | 웹앱 계정을 공간별로 분리한다 | 브라우저만 다룬다. Cadora는 파일·서버·에이전트까지 같은 경계로 묶는다 |
| GitHub Codespaces, Dev Container | 코드 개발환경(도구·패키지)을 표준화한다 | 코드 환경만 다룬다. Cadora는 탭·자료·서비스 체크리스트 같은 코드 밖 환경까지 배포한다 |
| Workona 등 탭·링크 공유 | 프로젝트 링크·문서를 팀과 공유한다 | 브라우저 안에서만 동작한다 |

Cadora만의 영역은 **팀 단위 환경 배포**와 **팀원 에이전트 사이의 공유 자원 충돌 조율**이다.

## 2. 대상 사용자와 핵심 시나리오

| 페르소나 | 현재 불편 | Cadora로 얻는 가치 |
|---|---|---|
| 여러 과제와 팀플을 병행하는 대학생 | 학교·개인 계정 혼용, 자료와 다운로드 혼재, 프로젝트 전환 시 재설정 | 개인 워크스페이스로 각각 분리하고 동시에 유지 |
| 팀장/프로젝트 리드 | 신입 팀원 개발환경 설치와 자료 안내에 반복 시간 소요 | GUI로 공통 환경 구성 후 초대와 자동 동기화 |
| AI 에이전트를 활용하는 개발 팀원 | 다른 팀원의 에이전트 작업과 공유 파일 변경을 모르고 진행 | 작업 제목·브랜치·변경 파일·위험 경고로 충돌 예방 |
| 지도교수/멘토 (후순위) | 팀 자료와 결과물을 확인하려면 별도 요청 필요 | 열람 전용으로 공용 자료와 배포 링크만 확인 |

- **1차 타깃**: 여러 프로젝트를 병행하는 CS 학생 및 소규모 개발 팀.
- **2차 타깃**: 소규모 스타트업·프리랜서·에이전시.

### 2.1 사용자 스토리

- **US-01 개인 작업**: "컴파일러 과제"와 "캡스톤 팀플"을 켜둔 채, 각각 다른 구글 계정과 실행 서버를 유지하고 싶다.
- **US-02 팀 합류**: 초대 수락만으로 저장소, 공용 탭, 자료, 실행 스크립트를 받아 프로젝트를 실행하고 싶다.
- **US-03 AI 실행**: 팀 프로젝트 폴더에서 Claude Code 또는 Codex를 작업 제목과 함께 실행하고 상태를 확인하고 싶다.
- **US-04 사전 경고**: 팀원 에이전트가 DB 스키마를 변경했거나 비슷한 기능을 작업하는 상황을 머지 전에 알고 싶다.
- **US-05 개인 정보**: 팀에는 작업 제목과 변경 파일 경로만 공유하고, 프롬프트·코드 내용·개인 로그인은 공유하지 않고 싶다.

## 3. 제품 목표 및 비목표

### 3.1 MVP 목표 (제품 방향 확정, 수치는 검증용 제안)

| 목표 | 측정 방법 | 제안 성공 기준 |
|---|---|---|
| 환경 격리 | 서로 다른 워크스페이스 동시 실행 테스트 | A/B 세션·폴더·설정 간 의도치 않은 혼합 0건 |
| 빠른 팀 합류 | 새 기기에서 초대→실행 준비 완료 시간 측정 | 사전 설치된 의존성 기준 10분 이내, 사용자 조사로 조정 |
| AI 작업 가시화 | 에이전트 실행, 상태 및 파일 변경 반영 여부 | 테스트 시나리오에서 시작·종료·변경 파일 확인 가능 |
| 충돌 사전 경고 | 위험 파일 두 명 동시 변경 시나리오 | 머지 전 경고 표시 및 근거 확인 가능 |
| 프라이버시 준수 | 송수신 메타데이터 점검 | 코드 본문·원문 프롬프트·개인 인증정보 비전송 |

위 시간·정량 목표는 기존 대화에서 합의된 수치가 아니라 PRD 관리를 위해 제안한 초기 기준이며, 사용자 테스트 후 조정해야 한다.

### 3.2 범위 밖 (MVP에서 만들지 않음)

- 자체 코드 에디터, IDE 대체, 자체 AI 모델 운영.
- 터미널 멀티플렉서·에이전트 상태 감지 엔진을 처음부터 개발하는 것 (Herdr 등 기존 런타임을 활용한다).
- Discord를 대체하는 일반 채팅·음성 기능.
- 모든 OS 앱의 창 배치/포커스 복원, 시스템 전역 채널별 알림 필터링.
- 모든 외부 AI 도구의 내부 대화 및 원격 에이전트 상태 완전 추적.
- OpenTelemetry 토큰·비용 계측, 팀 API 프록시 기반 비용 청구, 원격 공용 개발 서버.
- 완전한 컨테이너/가상머신 수준 보안 격리와 모든 프로젝트의 자동 포트 재매핑.

### 4.2 공통 UX 원칙

- 작업 도구를 교체하지 않는다. 코드 편집은 VS Code/Cursor 같은 외부 앱에서 수행한다.
- 동시 실행을 기본 가정한다. 활성 1개, 백그라운드 여러 개, 잠자기 상태를 구분한다.
- 팀 공유와 개인 사용을 분리한다. 팀장의 공통 설정 변경이 개인 로그인·개인 탭·메모를 덮어쓰지 않는다.
- 자동 실행은 설명 가능하고 취소 가능해야 한다. 저장소/스크립트 업데이트·설치·프로세스 재시작은 결과 및 실패 원인을 보여준다.
- 충돌 감지는 조언이지 차단이 아니다. 오탐 가능성을 표시하고 사용자가 판단한다.
- 관찰 수준을 숨기지 않는다. 에이전트 정보가 Herdr·Hooks·프로세스 감시 중 무엇에서 왔는지 표시한다.

## 5. 기능 요구사항

우선순위 정의: **P0** = 한 학기 핵심 시연/MVP, **P1** = MVP 안정화 또는 일정 여유 시, **P2** = 이후 확장. 아래 세부 수용 기준 및 우선순위는 원본 기획을 실행 가능한 형태로 구체화한 PRD 제안이다.

### 5.1 워크스페이스 생성·격리·동시 실행

#### FR-01 · 워크스페이스 목록 및 생성 [P0]

- 사용자는 개인/팀 워크스페이스를 생성·이름 변경·조회할 수 있다.
- 생성 시 유형(과제/개발 팀플/공모전·문서/직접 설정), 프로젝트 폴더, 고정 탭, 실행 스크립트를 지정한다.
- 목록에는 개인/팀 여부와 활성·백그라운드·잠자기 상태가 표시된다.
- **수용 기준**: 개인 워크스페이스 2개를 만들고 서로 다른 설정을 저장·재실행해도 유지된다.

#### FR-02 · 브라우저 로그인 세션 분리 [P0]

- 내장 브라우저는 워크스페이스별 독립 세션(partition)을 기본으로 사용한다.
- 사용자 선택에 따라 세션 공유를 허용하는 옵션은 실험 기능으로 둔다.
- **수용 기준**: A에서 로그인하거나 로그아웃해도 B의 쿠키/로그인 상태가 의도치 않게 변경되지 않는다.
- **제약**: 외부 사이트(특히 Google 계정)가 내장 브라우저 로그인 자체를 제한할 수 있다. 0주차에 대표 서비스(Google, 학교 LMS) 호환성을 검증하고, 막히는 서비스는 워크스페이스별 별도 프로필로 외부 브라우저(Chrome/Edge)를 띄우는 모드(P1)를 대안으로 둔다.

#### FR-03 · 터미널·실행 환경 분리 [P0]

- 워크스페이스별 작업 폴더(cwd), 지정 환경변수 및 실행 스크립트를 적용한 내장 터미널을 제공한다.
- 서버의 시작·종료·오류 상태를 보여주고, 서로 다른 워크스페이스 프로세스를 개별 제어한다.
- 터미널과 프로세스 실행은 에이전트 런타임 어댑터(§7.2)를 거친다. Windows 기본 셸은 PowerShell이다.
- **수용 기준**: A/B 터미널이 다른 폴더에서 실행되며 A 프로세스를 종료해도 B 프로세스는 영향받지 않는다.

#### FR-04 · 동시 실행 및 잠자기 [P0/P1]

- [P0] 여러 워크스페이스의 프로세스를 동시에 실행하고 전면 표시 대상만 변경한다.
- [P0] 각 워크스페이스의 활성/백그라운드 상태와 실행 중인 서버·에이전트를 보여준다.
- [P1] 잠자기 상태에서는 브라우저/탭 리소스를 줄이고 서버 유지 여부는 사용자 설정을 따른다.
- [P1] Herdr 런타임을 쓰면 Cadora를 닫거나 업데이트해도 에이전트·터미널이 계속 실행되고, 다시 열면 이어서 보여준다.
- **수용 기준**: A 화면을 보면서 B의 서버와 에이전트가 계속 동작한다. 잠자기는 프로세스 강제 종료와 구별된다.

#### FR-05 · 다운로드와 로컬 파일 분류 [P0]

- 내장 브라우저에서 받은 파일은 현재 워크스페이스의 지정 다운로드 폴더에 저장한다.
- 파일 저장 위치를 알리고 폴더 열기 기능을 제공한다.
- **수용 기준**: A/B에서 동일 파일명으로 다운로드해도 서로 다른 지정 폴더에 들어간다.

#### FR-06 · 프로젝트별 로컬 주소/포트 관리 [P1]

- 지원되는 스크립트에 대해 포트 지정과 프로젝트별 `.localhost` 별칭을 제공한다.
- 서버 주소 및 충돌 발생 시 대체 포트/수동 조치 안내를 제공한다.
- **수용 기준**: 명시적으로 구성한 개발 서버 두 개를 서로 다른 포트로 실행하고 워크스페이스별 주소로 접근한다.
- **제약**: 기존 서버가 포트 변경 인자를 지원하지 않을 수 있다. 모든 프로그램의 자동 포트 충돌 해결을 약속하지 않는다.

### 5.2 팀 워크스페이스와 환경 공유

#### FR-07 · 팀 생성·초대·권한 [P0]

- 팀장이 워크스페이스를 생성하고 팀원을 초대한다.
- 팀장/팀원/열람자 역할을 모델링한다. 열람자 UI는 P1로 둘 수 있다.
- 팀원은 초대를 수락하면 자신의 앱 사이드바에서 팀 워크스페이스를 확인한다.
- 로그인은 GitHub OAuth Device Flow를 쓴다. 개발·시연용 간이 로그인을 별도로 둔다.
- **수용 기준**: 노트북 A에서 만든 팀 워크스페이스가 초대 수락 후 노트북 B에 표시된다.

#### FR-08 · 공유 층 / 개인 층 분리와 동기화 [P0]

| 공유 층 (팀 동기화) | 개인 층 (기기·사용자별 유지) |
|---|---|
| 저장소, 기준 브랜치, 폴더 구조, 실행 스크립트 | 로그인 쿠키, 사용자별 서비스 계정 |
| 고정 탭, 공용 자료, 필요 서비스 체크리스트 | 개인 탭, 창 배치, 개인 메모 |
| 팀 AI 규칙, 공통 환경설정, 권한 있는 비밀값 참조 | 개인 알림 선호, 로컬 환경 덮어쓰기 |

- 팀장 변경은 버전과 함께 동기화하되 개인 층은 수정하지 않는다.
- 동기화 성공·실패·대기 상태를 구성원별로 조회한다.
- **수용 기준**: A에서 고정 탭을 추가하면 B에 반영되며 B의 개인 탭은 유지된다.

#### FR-09 · 팀원 초기 환경 준비 [P0]

- 팀원에게 저장소 연결/클론, 설치 필요 여부, 실행 스크립트, 필수 로그인 서비스 목록을 단계별로 안내한다.
- git clone, 패키지 설치, Docker 실행 같은 명령은 실행 전 확인 및 로그를 제공한다.
- 일부 로그인 작업이 미완료여도 사용자가 워크스페이스에 진입할 수 있도록 한다.
- **수용 기준**: 초대 수락→환경 준비 단계→완료 또는 조치 필요 항목 안내→워크스페이스 진입 흐름을 재현한다.

#### FR-10 · 공용 비밀값 연동 [P1, 보안 설계 선행]

- 팀 공유 비밀값의 등록·참조·역할별 사용 권한·교체/폐기 흐름을 정의한다.
- UI에서는 원문을 불필요하게 노출하지 않고 실행 시점에 권한 있는 프로세스에 제공한다.
- **수용 기준**: 허용된 팀원만 테스트 비밀값을 이용해 데모 스크립트를 실행할 수 있으며 권한 변경 후 새로운 요청이 거절된다.
- **중요**: 로컬 PC에 값을 전달하면 사용자가 추출할 수 있으므로 "값을 절대 볼 수 없음" 및 "팀 탈퇴 후 이미 받은 값도 완전히 회수"는 보장할 수 없다. 실제 서비스 출시 전 신뢰 경계, 키 교체, 서버 프록시 또는 제3자 비밀관리 서비스 연동을 결정해야 한다.

### 5.3 AI 에이전트 실행 및 팀 작업 현황

#### FR-11 · CLI 에이전트 실행 및 상태 [P0]

- 사용자가 작업 제목과 CLI 도구(초기 대상: Claude Code)를 지정하면 해당 워크스페이스 폴더에서 실행한다. 작업 제목으로 브랜치 이름을 제안한다.
- 실행은 에이전트 런타임 어댑터를 거친다. Herdr 어댑터는 워크스페이스별 Herdr 세션 안에서 에이전트를 실행하고 상태(작업 중·확인 필요·완료·대기)를 이벤트로 받는다. node-pty 어댑터는 Hooks와 프로세스 생존 여부로 상태를 판단한다.
- 실행 시작/종료, 상태, 작업 제목, 브랜치, 마지막 활동 시점, 관찰 수준(herdr·hooks·process)을 기록한다.
- Codex 등 다른 CLI는 같은 추상화로 실행·상태·파일 감시까지 지원하고, 도구별 깊은 통합은 순차 지원한다.
- **수용 기준**: 사용자가 "회원가입 API 구현"이라는 제목으로 에이전트를 실행하고 상태·폴더·브랜치를 확인할 수 있다. 에이전트가 사용자 입력을 기다리면 "확인 필요"로 표시된다.

#### FR-12 · 파일/Git 변경 감시 [P0]

- 프로젝트 폴더에서 추가/수정/삭제된 파일의 경로와 시점을 감지한다.
- Git 브랜치 및 작업 트리 상태와 연결하고 변경 파일을 API/의존성/DB 스키마/인프라 등으로 분류한다.
- `.git`, `node_modules`, 빌드 결과물 등 과도한 감시 대상은 기본 제외한다.
- **수용 기준**: `schema.prisma`, `package.json`, `docker-compose.yml`의 변경이 화면에 적절한 분류로 표시된다.
- **한계**: 파일 변경만으로 작성 주체가 AI인지 사람인지 항상 확정할 수 없다.

#### FR-13 · Claude Code Hooks 연동 [P0]

- Cadora가 실행한 Claude Code 세션에 Hook 설정을 넣고, Hook 이벤트를 로컬(127.0.0.1) 수신기로 받는다. 실행마다 토큰을 발급해 다른 프로세스가 보낸 위조 이벤트를 거른다.
- Hooks는 파일 단위 변경(어떤 파일을 수정했는지)과 세션 시작·종료 정보를 보강한다. 에이전트 상태는 Herdr를 쓸 때 Herdr의 판단을 우선한다.
- 원본 이벤트는 메모리에서 최소 메타데이터로 정제한 뒤 버린다. 사용자 프롬프트 원문, 코드 본문, 도구 응답 전문은 팀 서버에 보내지 않고 로그에도 남기지 않는다.
- Cadora가 꺼져 있거나 수신에 실패해도 Hook이 에이전트 동작을 막지 않는다.
- 이벤트 파서와 도구 연동 계층을 분리해 CLI 업데이트에 대응한다.
- **수용 기준**: 테스트용 도구 실행 이벤트를 수신하고 연결된 에이전트 카드의 최근 활동을 갱신한다.
- **한계**: 외부 터미널에서 실행한 에이전트는 hooks가 설정되지 않으면 파일·Git 단서 중심으로만 감지한다.

#### FR-14 · 팀 AI 작업 현황 패널 [P0]

- 팀원별 진행 작업 제목, 사용 도구, 실행 상태, 브랜치, 최근 변경 파일 경로를 표시한다.
- 비활성 팀원의 개인 워크스페이스 이름이나 작업 내용은 표시하지 않는다.
- 코드 본문·프롬프트 원문은 기본적으로 수집·공유하지 않는다.
- *(v1.2 제안)* 팀 현황은 그래프와 '팀 활동' 피드로도 보여준다. 활동 피드는 Cadora 알림·경고 전용이며, 팀원 간 대화·음성은 Discord(FR-17)로 연결한다. 일반 채팅은 계속 범위 밖이다(§3.2).
- **수용 기준**: 팀원 A/B가 각자 실행한 에이전트의 작업 제목과 상태가 양쪽 패널에 반영된다.

#### FR-15 · 충돌 가능성 사전 경고 [P0]

- **유사 작업**: 작업 제목 유사성 또는 관련 디렉터리 변경 중복을 이용해 경고.
- **공유 자원**: 마이그레이션·DB 스키마 파일·의존성 설정 등 충돌 가능성이 높은 변경 탐지.
- **환경 변경**: `docker-compose.yml` 같은 인프라 파일 변경 시 재시작 확인 안내.
- 경고에는 원인·관련 파일·작업 주체(공유 허용 범위)·조치 버튼을 표시한다.
- 경고는 서버가 이벤트를 받을 때 **받는 사람별로** 만들고 저장한다. 판단 규칙은 데스크톱과 서버가 같은 공통 규칙 모듈(프로토타입 `sim.js` 이식)을 쓴다.
- 경고를 만든 쪽에는 내용 없이 "○○에게 알림 보냄"만 표시한다. 사용자는 경고마다 오탐 여부를 피드백할 수 있다.
- **수용 기준**: A가 DB 스키마 파일을 변경하고 B가 관련 작업 중이면 B에 경고가 표시된다. 사용자는 경고를 무시하거나 근거를 확인할 수 있다.
- **한계**: MVP는 파일경로/규칙 기반 "충돌 가능" 알림이다. 코드 의미 수준의 정확한 충돌 판정이나 자동 중재를 보장하지 않는다.

#### FR-16 · 경고를 에이전트에 전달 [P1]

- 사용자가 경고를 승인하면 해당 변경 요약을 지원되는 CLI 에이전트에 추가 맥락으로 전달한다.
- 전달은 에이전트 런타임 어댑터로 한다(Herdr 사용 시 에이전트 입력 API). 에이전트가 작업 중이면 기다렸다가 확인 필요·대기 상태가 되면 전달한다.
- 사용자가 확인하지 않은 임의 명령이나 프롬프트는 실행하지 않는다.
- **수용 기준**: 사용자가 '내 에이전트에게 알려주기'를 누른 후 경고 요약이 에이전트에 전달되었다는 상태를 확인할 수 있다.

#### FR-17 · Discord 바로가기 [P1]

- 팀 워크스페이스에서 연결된 Discord 채널 링크를 표시하고 외부 앱/브라우저로 연다.
- 메시지 배지 또는 자동 상태 반영은 권한·API 가능성을 확인한 뒤 확장한다.
- 일반 채팅·음성 기능은 Cadora 내부에 재구현하지 않는다.

### 5.4 정보 보호와 개인정보 제어

#### FR-18 · 공유 범위 제어 [P0]

- 팀 동기화 데이터는 작업 제목, 에이전트 상태, 브랜치, 파일 경로, 분류, 경고 등 최소 메타데이터에 한정한다.
- 개인 로그인 세션, 쿠키, 토큰, 개인 워크스페이스 명칭, 코드/프롬프트 본문은 팀 서버에 기본 전송하지 않는다.
- 공유가 필요한 경우 사용자에게 명확한 설정과 미리보기를 제공한다.
- 금지 항목 검사는 데스크톱이 보내기 전과 서버가 받을 때 두 번 한다. 걸린 이벤트는 서버가 저장하지 않고 거부한다.
- **수용 기준**: 네트워크 요청/서버 저장 데이터를 점검했을 때 금지 항목이 없으며 공유 범위 전환을 사용자가 확인할 수 있다.

#### FR-19 · 자격증명·실행 안전 [P0 기본, P1 강화]

- 프로세스 실행 명령에 대한 명시적 확인, 최소 권한, 작업 로그 및 실패/복구 안내를 제공한다.
- 인증 정보·비밀값은 로그와 원격 이벤트에 마스킹한다.
- 파일·Git 감시에는 민감 파일 경로/내용 제외 규칙을 적용한다.
- **수용 기준**: 테스트 토큰이 Cadora UI·로그·WebSocket 페이로드에 원문 노출되지 않는다.

### 5.5 일정과 마감 *(v1.2 제안)*

#### FR-20 · 일정·마감 모아보기 [P1]

- 사용자가 속한 워크스페이스의 일정과 과제 마감을 주간 캘린더와 '오늘' 타임라인으로 모아 보여준다. 워크스페이스마다 색을 구분한다.
- 마감별 남은 할 일 체크리스트와 진행률(D-day)을 표시한다. 팀 워크스페이스의 체크리스트는 팀원과 함께 보고, 개인 워크스페이스의 일정·마감은 본인에게만 보인다.
- 할 일·칸반 같은 프로젝트 관리 기능으로 확장하지 않는다(§1.4). 워크스페이스에 붙은 마감을 확인하는 범위에 머문다.
- **수용 기준**: 두 팀원이 각자 화면에서 공통 팀 마감은 같게 보고, 상대의 개인 워크스페이스 일정·이름은 보지 못한다.

## 6. 핵심 사용자 플로우

### 6.1 개인 워크스페이스 생성

1. 홈에서 새 워크스페이스 선택.
2. 과제/개발 팀플/공모전/직접 설정 중 유형 선택.
3. 이름, 작업 폴더, 브라우저 세션, 다운로드 폴더, 고정 탭 및 시작 스크립트 설정.
4. 생성 후 탭과 터미널을 열고 필요 시 서버 실행.
5. 다른 워크스페이스로 전환해도 이전 환경의 프로세스는 설정에 따라 유지.

### 6.2 팀장 환경 배포 → 팀원 온보딩

1. 팀장이 팀 워크스페이스 생성 및 공통 환경 설정.
2. 저장소·고정 탭·스크립트·공용 자료·필요 서비스·AI 규칙을 등록.
3. 팀원 초대, 권한 부여.
4. 팀원은 초대를 수락하고 필요한 구성과 확인 항목을 안내받음.
5. 구성 완료 후 각자 계정으로 로그인하며 개인 설정은 별도 유지.
6. 이후 팀장이 공유 탭 등을 변경하면 팀원의 워크스페이스에 반영.

### 6.3 AI 에이전트 병렬 작업 → 사전 경고

1. 팀원 A가 작업 제목 "회원가입 API 구현"으로 Claude Code 실행.
2. 팀원 B가 다른 브랜치에서 로그인·회원 인증 API 작업 시작.
3. 에이전트 실행 상태와 파일 변경을 팀 메타데이터 서버로 공유.
4. A가 DB 스키마를 수정하면 B 화면에 DB 스키마 충돌 가능 경고 표시.
5. B는 변경 파일·관련 브랜치를 확인하고 작업 방식 조정, 필요 시 Discord로 소통.
6. 시스템은 경고를 제공하되 작업을 강제 중지하지 않음.

### 7.2 에이전트 런타임과 Herdr 활용 범위

| Herdr가 맡는 것 | Cadora가 맡는 것 |
|---|---|
| 에이전트·터미널 실행, 세션 유지(앱을 닫아도 계속 실행), 에이전트 상태(작업 중·확인 필요·완료·대기) 감지, 에이전트 입력 전달 | 브라우저 세션 격리, 다운로드 분기, 비밀값, 파일·Git 감시와 분류, Hooks 기반 파일 단위 기록, 팀 동기화, 충돌 경고 |

- **연결**: 워크스페이스 1개 = Herdr 세션 1개. Herdr 로컬 소켓 API(줄 단위 JSON, Windows는 named pipe)로 제어하고 상태 변화 이벤트를 구독한다.
- **터미널 화면**: 앱 안에서 Herdr 터미널에 연결한 뷰를 보여주거나, 사용자가 쓰던 터미널에 맡긴다. 앱 안에서 코드를 편집하는 기능은 만들지 않는다.
- **차별점**: Herdr는 한 사람용 도구이고 팀 기능이 없다. Cadora는 팀 환경 배포, 팀원 간 충돌 조율, 터미널 밖 환경 격리를 맡는다.
- **의존성 관리**: 사용 버전의 라이선스(현재 Apache 2.0, 과거 버전은 AGPL-3.0)와 API를 확인해 버전을 고정하고, 연동 코드는 어댑터 안에만 둔다.
- **대체 경로**: Herdr를 쓸 수 없으면 node-pty(ConPTY)로 직접 실행하고, 상태는 Hooks와 프로세스 생존 여부로 판단한다.

### 7.3 인터페이스 경계

세부 명세(엔드포인트, 메시지 필드, 오류 코드)는 [`API.md`](API.md)에서 팀이 함께 작성한다. PRD는 아래 다섯 경계와 원칙만 정한다.

| 경계 | 방향 | 원칙 |
|---|---|---|
| 서버 REST | 데스크톱 → 서버 | 인증, 팀 워크스페이스·멤버·초대, 공유 설정(버전 + 낙관적 동시성), 온보딩·적용 상태, 경고 조회·처리 |
| 서버 WebSocket | 양방향 | 이벤트 발행·전달은 최소 1회, 클라이언트가 만든 이벤트 ID로 중복 제거. 경고는 받는 사람에게만. 설정 변경 알림, 접속 상태 |
| 데스크톱 IPC | 화면 ↔ 메인 프로세스 | 화면은 파일 시스템·프로세스에 직접 접근하지 않는다(contextIsolation) |
| 로컬 Hook 수신 | Claude Code → 데스크톱 | 127.0.0.1 전용, 실행별 토큰, 원본은 메모리에서 정제 후 폐기, 실패해도 에이전트를 막지 않음 |
| 에이전트 런타임 어댑터 | 데스크톱 내부 | Herdr·node-pty 구현을 바꿔 끼울 수 있고, 도구별 상태값을 Cadora 공통 상태로 변환한다 |

### 7.5 동기화와 이벤트 처리 원칙

- 정적 구성은 버전 단위로 저장하고 클라이언트가 변경분을 가져간다. 공유 설정 수정은 기준 버전이 최신일 때만 받는다.
- 팀 변경 중 탭·자료·링크는 즉시 반영하고, 설치·스크립트 실행·재시작은 사용자 승인 후 적용한다.
- 동적 작업 상태는 수명이 짧은 이벤트로 송신하며 마지막 활동 시각을 기록한다.
- 로컬 파일 경로는 프로젝트 기준 상대경로로 공유하고, OS 절대경로는 보내지 않는다.
- 연결이 끊기면 로컬 작업은 계속하고 이벤트를 큐에 쌓았다가, 복구 후 순서대로 다시 보낸다.
- 충돌 경고의 판단 근거를 기록해 사용자에게 설명한다.

### 7.6 구현상 주의사항

- Electron `session.fromPartition()`은 웹 세션을 분리하지만 OS 수준의 완전한 격리나 악성 프로세스 방어를 보장하지 않는다. 브라우저 뷰는 `WebContentsView`를 쓴다(`BrowserView`는 deprecated).
- Claude Code/Codex는 각 사용자의 합법적인 CLI 설치와 계정 인증을 이용한다. Cadora는 모델을 직접 호스팅하지 않고, 사용자의 AI 구독을 Cadora 자체 기능에 끌어다 쓰지 않는다.
- AI 도구가 임의의 시스템 폴더에 접근하지 못하도록 강제하려면 추가 샌드박싱이 필요하다. MVP의 '프로젝트별 AI 맥락'은 우선 실행 위치 및 전달 컨텍스트 관리를 의미한다.
- 외부 앱에서 실행된 에이전트는 프로세스 상태와 작업 제목을 완전히 파악하지 못할 수 있다.
- Herdr의 Windows 지원 성숙도와 버전별 API 차이는 0주차 스파이크에서 확인한다.

> **Windows 11 우선**: 기본 내장 셸은 PowerShell로 두고, Herdr의 named pipe 연결과 node-pty/ConPTY 호환성, 백슬래시 경로·드라이브 경계, 프로세스 트리 종료와 파일 잠금을 테스트한다. WSL2·Docker Desktop 설치를 MVP의 필수 조건으로 요구하지 않는다. macOS 확장을 위해 파일 시스템, 셸·프로세스 실행, 외부 앱 연동 등 OS 의존 기능은 별도 어댑터로 분리한다.

## 10. 검증 계획과 성과 지표

- 팀원에게 작업 제목·브랜치·파일 경로가 공유되는 것은 어느 수준까지 허용 가능한가?
- 지금 쓰는 VS Code/Claude Code/Discord를 유지하면서 Cadora를 추가 사용할 의향이 있는가?

### 10.2 운영 지표 (도입 후)

| 지표 | 정의 | 해석 |
|---|---|---|
| 워크스페이스 활성률 | 주간 1회 이상 여는 사용자의 비율 | 개인 기능의 반복 가치 |
| 팀 초대 완료율 | 발송된 초대 중 실제 워크스페이스 입장 비율 | 온보딩 품질 |
| 환경 준비 소요시간 | 초대 수락부터 최초 성공 실행까지 시간 | 팀 환경 공유 효과 |
| 경고의 유용성 | 표시된 경고 중 사용자가 유효하다고 평가한 비율 | 오탐 관리 |
| 팀별 활성 에이전트 수 | 일정 기간 팀 워크스페이스에서 기록된 실행 수 | 팀 AI 조율 사용 정도 |
| 개인정보 관련 이슈 | 의도치 않은 데이터 공유·로그 노출 건수 | 안전성 |

수익화 가설은 개인 무료 → 고급 개인 기능 유료 → 팀 공유/관리 플랜 → 기업 기능(SSO 등) 순서로 검토한다. 구체적인 가격 및 무료 워크스페이스 개수는 아직 검증되지 않았으므로 확정 정책으로 기재하지 않는다.

## 12. 발표/데모 시나리오

1. **독립 환경**: "컴파일러 과제"와 "캡스톤 팀플" 두 워크스페이스를 동시에 열고 서로 다른 세션·서버·다운로드 폴더를 확인한다.
2. **팀 환경 공유**: 팀장 노트북에서 고정 탭을 추가하면 팀원 노트북에 반영되는 것을 보여준다.
3. **AI 작업 시작**: 팀원 A가 회원가입 API 구현을, 팀원 B가 로그인·회원 인증 API를 각자의 Claude Code에 맡긴다.
4. **사전 충돌 감지**: A의 에이전트가 DB 스키마 파일을 변경하면 B 화면의 팀 AI 작업 패널에 DB 스키마 충돌 가능 경고와 관련 파일·브랜치가 나타난다.
5. **도구 역할 구분**: 실제 편집은 외부 도구, 대화·음성은 Discord, 에이전트 실행은 Herdr, 환경 격리·공유·AI 작업 조율은 Cadora가 담당한다는 점으로 마무리한다.
